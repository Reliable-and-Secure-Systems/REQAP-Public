# RISC-V Bare-Metal Backend & QEMU Execution

This module is the final stage of the pipeline. It is responsible for converting the PyTorch models and the theoretical MQF packings into deployable C-code, compiling them into raw RISC-V binaries, and executing them inside a QEMU emulator.

## Directory Structure
- **`scripts/`**: Contains Python scripts (like `generate_packed_c.py`) used to extract weights from PyTorch models and write them out as physical C arrays.
- **`firmware/`**: Contains the raw C source code (`*.c`), Headers (`*.h`), Assembly (`*.s`), Linker scripts (`*.ld`), and the `Makefile` required to compile the RISC-V binary.
- **`docs/`**: Contains detailed markdown reports detailing the memory load analyses and profiling metrics.

## Python to C Conversion Flow (Reproducibility)

To ensure full reproducibility, this backend automates the conversion of Python PyTorch models into bare-metal C arrays:

1. **Python Parsing (`scripts/generate_packed_c.py` & `generate_swin_packed_c.py`)**: 
   These scripts load the trained FP32/QAT PyTorch `.pth` models alongside the granular `.json` configurations generated by the MQF quantization framework.
2. **C-Array Generation (`firmware/generated/`)**: 
   The scripts extract the weights, pack them into 32-bit integers (following the Joint W=A Safe-FFD packing logic), and output them as flat 1D C-arrays in `weights.h` files. 
3. **Metadata Arrays (`pos[]`, `mask[]`, `slots[]`)**:
   Crucially, the scripts also generate tracking metadata arrays. These arrays dictate exactly how many bits each packed element contains, its bitwise mask, and its shift position within the register, enabling fully dynamic, heterogeneous multi-precision execution at runtime.
4. **C Kernel Execution (`firmware/swar_mac.c`)**: 
   The generated header files are included by the main C firmware. The `swar_mac_general()` function uses a lookup table and the `pos[]`/`mask[]` metadata arrays to dynamically unpack the 2/4/8-bit weights and activations, executing the MAC operations using efficient SWAR bitwise arithmetic.

## Execution Flow (How to Run)

Because standard compilation frameworks (like ONNX Runtime) do not support our custom MQF heterogeneous packing algorithm, we execute this backend in a two-step process: **Generation** followed by **Compilation & Execution**.

Ensure you are inside the `risc_v_backend/` directory before running these commands.

### Step 1: Generate the C-Headers
First, we use the Python script to physically dump the weights into C header files. The script will automatically place the generated files into the `firmware/generated/` folder so the C code can access them.

```bash
# Generate C arrays for VGG-11
python scripts/generate_packed_c.py --model VGG11
```

### Step 2: Compile the RISC-V Firmware
We use the custom `Makefile` inside the `firmware/` folder to compile the source code into an `.elf` binary for the `rv32im` architecture.
The C code utilizes **SWAR (SIMD Within A Register)** logic to dynamically unpack the multiple weights using bitwise `SHIFT` and `AND` instructions.

```bash
# Compile the bare-metal VGG-11 binary
make -C firmware vgg11_packed
```

### Step 3: Run the Firmware on QEMU
Finally, execute the compiled `.elf` firmware inside the QEMU emulator.

```bash
# Emulate the binary execution on the 'virt' machine board
make -C firmware run_vgg11_packed
```

*(This command will output the model's exact classification prediction and the hardware cycle/memory metrics directly to your terminal).*
